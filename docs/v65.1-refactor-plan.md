# v65.1 内部整理レビュー方針

## 前提
- `main` の v64 は現行運用版として固定し、整理中は変更しない。
- レビュー作業は `review/v65.1` で行う。
- v65.1 は機能追加版ではなく、v64 の見た目・操作・出力を維持した内部整理版とする。

## v65.1 の目的
1. 巨大な `index.html` の責務を整理する。
2. 写真保存処理の成功/失敗判定を正しくする。
3. 重複関数、未使用変数、未使用DOM参照、旧CSS上書きを整理する。
4. PWAのオフライン起動を維持する。
5. 次段階の保存容量対策・OneDrive連携を追加しやすい構造にする。

## 最優先の既知問題
### IndexedDB保存失敗の誤成功判定
現行の `savePhotoToIndexedDB(photo)` は書き込み失敗を内部でcatchし、呼び出し元へ例外を返さない。
そのため、実際にはIndexedDB保存に失敗しても `takePhoto()` 側が成功扱いで `capturedPhotos` へ追加し、「撮影しました」と表示できる。

v65.1では、保存失敗時は呼び出し元へ失敗を返し、保存成功前に撮影済み扱いしないよう整理する。

## v65.1 で整理する範囲
- HTML / CSS / JavaScript の責務分離準備
- 写真保存処理を PhotoStore 相当へ集約
- IndexedDBのopen / read / put / delete / importSession操作を一か所へ寄せる
- `loadImage()` 等の重複定義整理
- HTMLに存在しない旧DOM参照の整理
- 現行経路から呼ばれない旧関数の確認・削除
- v44〜v64で積み重なったCSS上書きを最終状態へ整理
- GitHubルートの旧 `script.js` を現行 `index.html` と比較し、不要なら削除
- 新しいファイル構成に合わせて Service Worker のキャッシュ対象を更新
